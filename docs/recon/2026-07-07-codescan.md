## STEP 2 — EXECUTED (one PR per concern; each independently correct, auto-resolves on merge)

### PR #202 — `fix/debug-formatstring` — resolves #15
`runsDebug` interpolated a caller-built `stage` into the **format-string position** of `console.log`
(`console.log(\`[runs-debug] ${stage}\`, …)`), so a `%s`/`%d` in `stage` could forge/misformat the line.
Moved `stage` to a separate argument → literal format string. No behavior change (console.log space-joins
args). **Proof:** typecheck + lint clean; the gated `[runs-debug]` funnel e2e (`detail.spec.ts "debug funnel"`)
passes — the asserted substrings are unchanged.

### PR #203 — `fix/pin-action-shas` — resolves #18–#27
Pinned 10 step `uses:` refs (checkout, setup-node, setup-python, dependency-review-action,
codeql-action/{init,analyze,upload-sarif}) to their **peeled commit SHA** (`gh api …/commits/TAG`), `# vX`
comment retained for readability + Dependabot updates. Config-only, CI workflows. **Proof:** exactly the 4
flagged files / 10 lines; all workflow YAML re-parses; every flagged `uses:` now a 40-char SHA.

### PR #204 — `fix/dependabot-cooldown` — resolves #16–#17
Added `cooldown: { default-days: 7 }` to both `package-ecosystem` entries (npm, github-actions) so Dependabot
waits 7 days after a version is published. Config-only. **Proof:** YAML parses; both `updates[]` carry the
cooldown.

### #28 — `js/http-to-file-access` (CodeQL, medium) — `contract/capture.mjs:118`

**OBSERVED.** The flagged line is the baseline-diff capture:
```js
const name = data && data.configured === false ? "baseline_diff_not_configured" : "baseline_diff_ok";
writeFileSync(join(dir, `${name}.json`), JSON.stringify(data, null, 2) + "\n");
```
- The write **path** is fully literal: `name` is one of two hardcoded strings; `dir` is
  `__dirname/real`. No response-controlled path component → **no path traversal**.
- The tainted flow CodeQL sees is response-body → file **content**. But writing the real API response to a
  fixture file **is the entire purpose** of `capture.mjs` (`capture:contracts`) — it mints
  `contract/real/*.json` for the contract tests.
- It is a **dev/CI tool**, run manually by a developer with their own admin token (`SYNTHWATCH_API_TOKEN`)
  against the **trusted** SynthWatch API. Not shipped, not attacker-reachable.

**INFERRED.** No real risk: literal path + intended content + trusted source + not in the deployed app. No
cheap true-fix exists — the taint is inherent to the tool's function (persist the response), and the path is
already literal, so there is nothing to sanitize without defeating the tool.

**Proposed dismissal (used in tests — it generates contract-test fixtures):**
```
gh api -X PATCH repos/craigoley/synthwatch-dashboard/code-scanning/alerts/28 \
  -f state=dismissed -f dismissed_reason="used in tests" \
  -f dismissed_comment="capture.mjs is the dev-only contract-fixture capture tool (capture:contracts). Write PATH is literal (name is one of two hardcoded strings; dir is __dirname/real — no traversal); the tainted 'content' is the trusted API response, which persisting to contract/real/*.json is the tool's entire purpose. Run manually with a dev admin token against the trusted API; not in the deployed app."
```

### #29 / #30 / #31 — `detect-non-literal-regexp` (Semgrep) — `scripts/check-enum-coverage.mjs:37,47,54`

**OBSERVED.** Three `new RegExp(...)` built from interpolated `table` / `column` / `unionName`:
```js
new RegExp(`CREATE TABLE\\s+(?:IF NOT EXISTS\\s+)?"?${table}"?\\s*\\(([\\s\\S]*?)\\n\\s*\\);`, "i")   // :37
new RegExp(`\\b${column}\\s+IN\\s*\\(([^)]*)\\)`, "i")                                                  // :47
new RegExp(`type\\s+${unionName}\\s*=\\s*([^;]*);`)                                                     // :54
```
- `table` / `column` / `unionName` come from **`enum-coverage.json`** (committed repo config) — the manifest
  of runner-enum → consumer-union mappings this CI guard checks. They are SQL identifiers / TS type names,
  **never runtime or user input**.
- The script (`scripts/check-enum-coverage.mjs`) runs **only in CI** (the enum-coverage check). There is no
  request path, no attacker-reachable surface; a ReDoS would require an attacker to already control the
  repo's committed config.

**INFERRED.** Not exploitable (trusted, developer-authored input; build-time only). No cheap fix *clears the
alert*: the rule is purely syntactic (any non-literal `RegExp` argument), and the patterns are inherently
parameterized by table/column/union name, so escaping the interpolants (a reasonable defense-in-depth for
config with regex metacharacters — noted below) would **not** silence it; only a full rewrite to avoid dynamic
regex would, which is disproportionate churn to a working guard for a non-exploitable finding.

**Proposed dismissal (false positive — trusted config input, CI-only):**
```
for n in 29 30 31; do
  gh api -X PATCH repos/craigoley/synthwatch-dashboard/code-scanning/alerts/$n \
    -f state=dismissed -f dismissed_reason="false positive" \
    -f dismissed_comment="check-enum-coverage.mjs is a CI-only guard; the RegExp interpolants (table/column/unionName) come from committed enum-coverage.json config (SQL identifiers / TS type names), never runtime or user input. No attacker-reachable surface → no ReDoS. Rule is syntactic (any non-literal RegExp); no fix short of rewriting the working guard would clear it."
done
```

**Optional defense-in-depth (does NOT clear the alert; offered for Craig's call):** wrap each interpolant in an
`escapeRegExp` helper so a config value containing a regex metacharacter is matched literally — a small
correctness hardening, independent of the (syntactic) Semgrep finding.
